# Contributing to OmniBlocks

Thank you for your interest in contributing to OmniBlocks! We believe that the future of AI is modular, and it is built by a community that works together.

By contributing, you agree to abide by our code of conduct and our philosophy of **AI-first development** as outlined in our `AGENTS.md`.

---

## 🚀 How to Contribute

### 1. Finding a Task

* Check our [GitHub Issues](https://www.google.com/search?q=---) page.
* Look for tags like `good first issue` or `help wanted`.
* If you have a feature request, please open an issue first to discuss it with the maintainers.

### 2. The Workflow

We maintain a high-velocity development cycle. Please follow these steps for every contribution:

1. **Fork the Repository:** Create your own fork of the main branch.
2. **Create a Branch:** Use a descriptive name (e.g., `feature/add-new-block` or `fix/memory-leak`).
3. **Utilize Agents:** As per `AGENTS.md`, use AI agents to assist in drafting your code, generating unit tests, and writing documentation.
4. **Local Testing:** Ensure all existing tests pass before submitting.
```bash
pytest tests/

```


5. **Submit a Pull Request:** Link your PR to the original issue. Provide a clear summary of your changes.

---

## 🛠 Development Guidelines

* **Modular Design:** When adding new blocks, ensure they follow the established interface in `base_block.py`.
* **Documentation:** All new features must include docstrings following the Google Python Style Guide.
* **AI Tagging:** Clearly mark code generated by AI agents with a comment at the top of the file/function:
```python
# GENERATED BY: [Agent Name/Model]

```


* **No Blanks:** Ensure all submitted code is complete. Do not leave placeholder comments or unfinished code blocks.

---

## ⚖️ Code of Conduct

We are committed to providing a friendly, safe, and welcoming environment for all.

* Be respectful and constructive in all discussions.
* Avoid unprofessional language.
* Respect the diverse backgrounds and skill levels of our community members.
